## 3. 接入位置与三个硬缺口

### 3.1 接入点已预留

```python
# interview_service.py:250-269（现状）
async def _deliver(db, session, payload) -> Dict[str, Any]:
    if session.interview_mode == INTERVIEW_MODE_AVATAR:
        return await avatar_interview.enter(db, session, payload)  # 数字人通道
    return payload                                                 # text：原样返回
```

`enter(db, session, payload)` 签名刻意带 `db`（供登记数字人会话 id），**只需填函数体**。

### 3.2 缺口 A：`_deliver` 只覆盖 1/4 入口

`_deliver` 全项目**只有 1 个调用点**：`interview_service.py:401`（`start_session` 末行）。
`submit_answer:497` / `get_current_question:422` / `end_session:575` **都未分流** ⇒ 数字人「语音作答（ASR）/ 重播当前题 / 播报结束语」无处挂载。

### 3.3 缺口 B：数据列缺失

`interview_session` 无 `avatar_session_id` / `stream_url`。`Base.metadata.create_all` **只建表不补列** ⇒ 必须同步 `utils/schema_sync.DESIRED_COLUMNS`（现仅 `interview_mode` 一列，见 `schema_sync.py:78-85`）。
`interview_answer.audio_url`（String(300)）**已存在**（`submit_answer:543` 写入），ASR 的现成接缝，**无需加列**。

### 3.4 缺口 C：前端零 avatar 能力

`InterviewRoom.vue:101-109` 的 `form` 只有 `job_id / interview_type / difficulty / total_questions / use_rag`——**没有 `mode`**。全仓 grep 确认前端无任何 avatar 代码。`frontend/package.json` **无播放器依赖**（现有：vue / element-plus / echarts / markdown-it）。

### 3.5 缺口 D：签名工具不可直接复用（但依赖已就绪）

`main.py:101-110` 的 `_make_url` **硬编码 `GET {path} HTTP/1.1`**（Spark X1 WebSocket 用）；讯飞虚拟人是 **POST + `host/date/request-line` 三段 HMAC-SHA256** ⇒ 算法同构、请求行不同。
**但 HTTP 客户端不需要新增依赖**：`requirements.txt:20` 已有 `httpx>=0.27.0`（`embedding_provider` 已在用，函数体内延迟导入）。v1 报告暗示要新增 HTTP 依赖，**此处更正**。

## 4. ★★ 测试影响表（v2 最重要新增）

`tests/test_avatar_channel.py` 是 58 套回归之一，它对「通道尚未接入」这一**当前状态**做了强断言。**一旦填 `enter()`，下列断言会逐个失败**，必须同步改测试：

| 节 | 断言（原文要点） | 填 `enter()` 后 | 处置 |
|---|---|---|---|
| [1] | `STATUS == STATUS_PENDING == "pending"` `:155` | ❌ 若改 `"ready"` 即挂 | 改 `STATUS` 时同步改断言 |
| [1] | `INTEGRATIONS == {"iflytek":False,"asr":False,"tts":False}` `:158` | ❌ 置 `True` 即挂 | 同步改断言 |
| [1] | `enter` 是协程、签名 `[db,session,payload]` `:161-164` | ✅ 不变 | — |
| [1] | `out is payload`（**返回同一对象**）`:171` | ⚠️ 见下 | 视设计 |
| [2] | `start` 返回**恰好 4 键** `{session,question,job_name,message}` `:205` | ⚠️ text 不受影响；但见 [4]/[6] | — |
| [4] | `enter` 被调用**恰好 1 次** `:248` | ✅ 不变 | — |
| [4] | `set(args[2]) == 4 键` `:255` | ❌ **若 `enter` 往 `payload` 里加键（原地改），spy 捕获的同一 dict 会变成 5 键** | 同步改断言 |
| [4] | `avatar_started is args[2]`（**返回同一对象**）`:260` | ❌ 若 `enter` **返回新 dict** 即挂 | 同步改断言 |
| [6] | HTTP `set(r.json()) == 4 键` `:362` | ❌ 若顶层新增 `stream_url` 等键即挂 | 见 §4.1 |
| [7] | `avatar_interview.py` 不得 import `websocket*`/`requests*`/`aiohttp` `:382` | ✅ **`httpx` 不在禁止集**，可过 | — |
| [7] | 不得 import `main` `:389` | ⚠️ 若在通道模块内直接调讯飞客户端，注意别引 `main` | 用独立客户端模块 |
| [7] | 不得 import `interview_core`/`interview_service` `:391` | ⚠️ 保持单向 | — |
| [7] | `enter` 函数体**只有一条 `return payload`** `:413` | ❌ **填函数体必然挂** | 必须改这条断言 |

| [7] | core 源码不含 `avatar_interview` `:404` | ✅ 不改 core 即满足 | — |

**结论：`test_avatar_channel.py` 至少 5 条断言（[1]×2、[4]×2、[7]×1）会被必然触发，另加 [6] 视设计。** 这不是「顺手改测试」，而是**接入动作的一部分**，必须在同一个改动里完成并全跑 58 套。

### 4.1 「顶层新增键」还是「嵌进 session」——一个真实的设计岔路

`test_avatar_channel.py:362` 要求 `start` 的 **HTTP 顶层出参恰为 4 键**。给数字人加字段有两种走法：

| 走法 | 顶层键数 | 对 [6] 的影响 | 评价 |
|---|---|---|---|
| **(a) 顶层新增** `stream_url` / `avatar_session_id` | 变 5~6 键 | ❌ 必挂，须改 [6] | 契约变化最大 |
| **(b) 嵌进 `session`**（`InterviewSessionOut` 加可选字段） | 顶层仍 4 键 | ✅ [6] 可过；但 `session` 子字典键数变化，**需核对是否有测试锁 session 键集** | 契约更稳，**推荐** |
| **(c) 复用 `warnings` / `message` 传非结构化信息** | 顶层仍 4 键 | ✅ | 不推荐：把结构化字段塞进文本，前端难解析 |

> 无论选哪种，都要在改完后**全跑 58 套**核对是否有其它套件锁了 `session` 的键集。
