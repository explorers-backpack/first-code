# 任务：生成下一道面试问题

你正在主持一场面试，请根据下面的配置、岗位、简历与进度，生成**下一道**面试问题。

## 一、面试配置

- 面试类型：{{interview_type}}
- 面试难度：{{difficulty}}
- 当前阶段：{{current_stage}}

## 二、目标岗位

- 岗位名称：{{job_title}}
- 岗位描述：{{job_description}}

## 三、候选人简历摘要

{{resume_summary}}

## 四、本场面试计划

{{interview_plan}}

## 四·五、参考知识（外部检索结果，可选）

参考知识：
{{knowledge_context}}

出题时请把这些知识融入问题的场景与追问点，但不得整段照抄进 `question`，
也不得把知识中的结论直接写进 `question`（`expected_points` 可参考）。

## 五、本场进度（用于避免重复）

已提问问题：
{{asked_questions}}

已覆盖知识点：
{{covered_topics}}

薄弱知识点（优先补强）：
{{weak_topics}}

## 六、生成要求

1. 只生成**一道**问题，且必须与「已提问问题」不重复——是**语义层面**的不重复，不仅是字面不同。
2. 优先围绕「当前阶段」出题：
   - introduction：自我介绍、职业概况
   - resume：简历中的任职经历与职责
   - technical：岗位要求的技术原理与实现细节
   - project：简历中的具体项目（做了什么、怎么做的、遇到什么问题、如何取舍）
   - scenario：场景设计、故障排查、方案权衡
   - hr：求职动机、团队协作、职业规划
   - closing：收尾确认
3. 优先补强「薄弱知识点」；其次覆盖尚未出现在「已覆盖知识点」中的计划知识点。
4. 难度必须与「面试难度」一致：
   - junior：基础概念与常规用法
   - mid：实现原理与常见坑
   - senior：架构取舍、边界条件与极限场景
5. 优先针对「目标岗位」与「候选人简历」的**交集**提问。简历中出现过的项目名称应被具体引用，不要用「你的某个项目」这类模糊指代。
6. 问题正文中不得包含答案、答案要点或评分标准。
7. `expected_points` 填写该题的关键采分点关键词（3-6 个），仅供内部评分使用，不得写进 `question`。
8. `reason` 用一句话说明「为什么在此刻问这道题」（对应阶段 / 补强薄弱点 / 覆盖计划知识点）。

## 七、输出格式（严格 JSON，不要 markdown 代码块，不要任何额外文字）

成功时输出：

{
  "question": "面试问题的完整文本",
  "question_type": "technical",
  "topic": "该题考察的知识点",
  "difficulty": "mid",
  "expected_points": ["采分点一", "采分点二"],
  "reason": "一句话说明出题理由"
}

无法生成有效问题时（例如：面试计划已完成、输入信息不足、无法与已问问题区分），输出：

{
  "question": "",
  "error": "说明无法生成的原因"
}

字段约束：

- `question`：字符串。成功时为非空的完整问题文本；失败时为空字符串 `""`。
- `question_type`：introduction / resume / technical / project / scenario / hr / closing 之一。
- `topic`：知识点名称，尽量直接使用技术名词本身。
- `difficulty`：junior / mid / senior 之一。
- `expected_points`：字符串数组，元素的语义是采分点关键词。
- `reason`：非空字符串，一句话即可。
