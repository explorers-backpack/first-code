# 任务：根据候选人刚才的回答生成**一道追问**

你正在主持一场面试。候选人刚刚回答了上一道问题，请针对这个回答的
**薄弱点 / 含糊处 / 未展开的细节**生成**一道**追问。

- 面试难度：{{difficulty}}
- 当前阶段：{{current_stage}}
- 本次为第 {{follow_up_no}} 次追问

## 二、目标岗位

- 岗位名称：{{job_title}}
- 岗位描述：{{job_description}}

## 三、候选人简历摘要

{{resume_summary}}

## 四、本题与候选人回答

上一道问题：
{{current_question}}

候选人回答：
{{candidate_answer}}

## 四·五、参考知识（外部检索结果，可选）

参考知识：
{{knowledge_context}}

也不得把知识中的结论直接写进 `question`（`expected_points` 可参考）。

## 五、回答分析（规则评分产出，供你判断追问方向）

{{answer_analysis}}

## 六、历史问答（用于避免重复与衔接上下文）

{{history_qa}}

{{asked_questions}}

{{covered_topics}}

薄弱知识点（优先补强）：
{{weak_topics}}

## 八、追问要求

1. 只生成**一道**问题，且必须是针对「候选人回答」的追问：
   - 回答里提到的技术名词 → 追问其原理、边界或取舍
   - 回答含糊或只有结论 → 追问「为什么」「怎么做」「数据是多少」
   - 回答里有具体项目 → 追问该项目中的实际决策与踩过的坑
2. 必须与「已提问问题」以及「历史问答」中的问题不重复——是**语义层面**的不重复，不仅是字面不同。
3. 优先追问「回答分析」中列出的**薄弱点**；其次追问「薄弱知识点」。
4. 难度必须与「面试难度」一致：
   - junior：基础概念与常规用法
   - mid：实现原理与常见坑
   - senior：架构取舍、边界条件与极限场景
5. 若回答已经足够完整、或没有可追问的空间，**不要硬造问题**——
   按「失败输出」返回空 `question`，并在 `error` 里说明原因。
6. 问题正文中不得包含答案、答案要点或评分标准，也不得直接引用「回答分析」的措辞。
7. `expected_points` 填写该题的关键采分点关键词（3-6 个），仅供内部评分使用，不得写进 `question`。
8. `reason` 用一句话说明「为什么在这里追问这一句」（对应薄弱点 / 未展开的细节）。

## 九、输出格式（严格 JSON，不要 markdown 代码块，不要任何额外文字）

成功时输出：

{
  "question": "追问的完整文本",
  "question_type": "technical",
  "topic": "该题考察的知识点",
  "difficulty": "mid",
  "expected_points": ["采分点一", "采分点二"],
  "reason": "一句话说明追问理由"
}

无法生成有效追问时（例如：回答已足够完整、输入信息不足、无法与已问问题区分），输出：

{
  "question": "",
  "error": "说明无法追问的原因"
}

字段约束：

- `question`：字符串。成功时为非空的完整问题文本；失败时为空字符串 `""`。
- `question_type`：introduction / resume / technical / project / scenario / hr / closing 之一。
- `topic`：知识点名称，尽量直接使用技术名词本身。
- `difficulty`：junior / mid / senior 之一。
- `expected_points`：字符串数组，元素的语义是采分点关键词。
- `reason`：非空字符串，一句话即可。
